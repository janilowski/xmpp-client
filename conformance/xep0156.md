# XEP-0156: alternative connection discovery

Partial client coverage, not a completed conformance claim. Reviewed on
2026-09-17 against [XEP-0156 1.4.0](https://xmpp.org/extensions/xep-0156.html)
§§2–4 and [RFC 6415](https://datatracker.ietf.org/doc/html/rfc6415)
§§2–4.1, §5 and Appendix A. Full dependency/errata review remains part of
[#8](https://github.com/janilowski/xmpp-client/issues/8).

## Profile and evidence

This is a browser-oriented WebSocket client. Discovery reads XRD, not JRD;
the additional JRD publication recommendation applies to servers. There is no
BOSH transport, TCP/SRV procedure or removed `_xmppconnect` TXT lookup.
Explicitly configured `ws://` remains application policy, not secure discovery.

The parser tests cover malformed XML, namespaces, missing/invalid addresses,
unsuccessful HTTP responses and cancellation after the decompressed byte limit.
These defensive limits are local policy, not XEP-prescribed numeric values.
The mutation runner deliberately removes ordering and template checks; assertions
must detect both defects.

## Remaining audit work

- Exercise stalled response headers and bodies over real HTTPS. Passing an
  `AbortSignal` and simulating a rejected fetch do not prove the deadline works.
- Verify redirect rejection with real peers, including HTTPS-to-HTTP downgrade.
  Current `redirect: "error"` deliberately deviates from RFC 6415 §2's SHOULD
  follow redirects: browser manual redirects conceal the target, while automatic
  following cannot enforce an HTTPS-only chain. Document the browser API evidence
  and interoperability cost before considering this boundary closed.
- Complete inherited XRD/URI processing and errata review; extend adversarial
  representation/link tests where that review identifies missing requirements.
- Finish RFC 7590/current BCP 195 mapping and runtime delegation review. This
  discovery map does not establish TLS version, cipher or session compliance.
- Publish reviewed maps, fixes and tests before closing #8.
