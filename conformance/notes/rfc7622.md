# RFC 7622: review notes

Migrated from the 2026-07-29 inventory. These are **unverified review notes**,
not a complete extraction or a compliance claim. Preserve IDs when adding tests;
check the original clause, its conditions and errata before implementation.
Executable coverage belongs in the standard's suite and coverage map, not here.

## RFC7622-address-domain-length

RFC 7622 §3.2; SHOULD; client; responsibility: library.

When: When preparing or accepting a JID domainpart

Require 1 through 1023 UTF-8 octets and respect underlying DNS length limits.

## RFC7622-address-domain-prep

RFC 7622 §3.2; SHOULD; client; responsibility: library.

When: When preparing or accepting a JID domainpart

Apply IDNA2008 preparation, lowercase mapping, and the verified RFC 5895 erratum; account for held domain-separator errata 5769 and 5789.

## RFC7622-address-localpart-length

RFC 7622 §3.3; SHOULD; client; responsibility: library.

When: When a JID contains a localpart

Require 1 through 1023 UTF-8 octets.

## RFC7622-address-localpart-prep

RFC 7622 §3.3; SHOULD; client; responsibility: library.

When: When preparing or accepting a JID localpart

Apply the UsernameCaseMapped PRECIS profile and the XMPP localpart exclusions.

## RFC7622-address-resource-length

RFC 7622 §3.4; SHOULD; client; responsibility: library.

When: When a JID contains a resourcepart

Require 1 through 1023 UTF-8 octets.

## RFC7622-address-resource-prep

RFC 7622 §3.4; SHOULD; client; responsibility: library.

When: When preparing or accepting a JID resourcepart

Apply the OpaqueString PRECIS profile, allowing leading space as clarified by verified erratum 4560.

## RFC7622-address-resource-opacity

RFC 7622 §3.4; SHOULD NOT; client; responsibility: library.

When: When interpreting a resourcepart

Do not infer application semantics from the resourcepart value.

## RFC7622-client-preparation

RFC 7622 §5.1; SHOULD; client; responsibility: library.

When: Before constructing or sending a JID

Prepare each present JID part and reject values that cannot be prepared.

## RFC7622-idna2008-support

RFC 7622 §6.3; MUST; both; responsibility: library.

When: For internationalized domainparts

Support IDNA2008 rather than relying solely on the obsolete IDNA2003 rules.

## RFC7622-ipv6-zone-ui-update

RFC 7622 §Updated by RFC 9844 section 5; MUST; both; responsibility: deployment.

When: For a user interface accepting non-global IPv6 literals with zone identifiers

Provide a way to enter the address and zone identifier.

Scope: not-applicable. The library provides no address-entry user interface, and RFC 9844 states that this UI requirement does not apply to URIs fetched by browsers.
