# RFC 7395: review notes

Migrated from the 2026-07-29 inventory. These are **unverified review notes**,
not a complete extraction or a compliance claim. Preserve IDs when adding tests;
check the original clause, its conditions and errata before implementation.
Executable coverage belongs in the standard's suite and coverage map, not here.

## RFC7395-handshake-request-subprotocol

RFC 7395 §3.1; MUST; client; responsibility: shared.

When: During the WebSocket opening handshake

Offer xmpp in the WebSocket subprotocol list.

## RFC7395-handshake-response-subprotocol

RFC 7395 §3.1; MUST; server; responsibility: server.

When: When accepting an XMPP WebSocket connection

Select xmpp as the WebSocket subprotocol.

Scope: not-applicable. Server handshake behavior; the client rejection behavior is tracked separately.

## RFC7395-handshake-reject-missing-subprotocol

RFC 7395 §3.1; MUST; client; responsibility: library.

When: When the WebSocket response does not select xmpp

Close the WebSocket and do not establish an XMPP connection.

## RFC7395-messages-conform

RFC 7395 §3.1; MUST; client; responsibility: library.

When: After a successful WebSocket handshake

Send and accept only messages conforming to the XMPP WebSocket subprotocol.

## RFC7395-text-utf8

RFC 7395 §3.2; MUST; both; responsibility: shared.

When: For every XMPP WebSocket data message

Use a WebSocket text message containing UTF-8 XML.

Scope: delegated. The browser frames text, while the library supplies and parses its XML content.

## RFC7395-framing-namespace

RFC 7395 §3.3.2; MUST; client; responsibility: library.

When: For open and close stream frames

Use the urn:ietf:params:xml:ns:xmpp-framing namespace.

## RFC7395-invalid-framing-namespace

RFC 7395 §3.3.2; MUST; client; responsibility: library.

When: When receiving an open or close frame in the wrong namespace

Close the stream with invalid-namespace.

## RFC7395-standalone-xml

RFC 7395 §3.3.3; MUST; both; responsibility: library.

When: For each WebSocket message carrying an XMPP frame

Make the frame independently parsable XML with all required namespace and language declarations.

## RFC7395-omit-xml-declaration

RFC 7395 §3.3.3; SHOULD NOT; both; responsibility: library.

When: When serializing a WebSocket XMPP frame

Do not include an XML declaration.

## RFC7395-frame-first-character

RFC 7395 §3.3.3; MUST; both; responsibility: library.

When: For every XMPP WebSocket frame

Start the frame with the less-than character.

## RFC7395-one-element-per-frame

RFC 7395 §3.3.3; MUST; both; responsibility: library.

When: When sending a stanza, stream header, or other top-level element

Send exactly that element in its own WebSocket message.

## RFC7395-stream-prefix-declaration

RFC 7395 §3.3.3; MUST; both; responsibility: library.

When: When a standalone frame uses the stream namespace prefix

Declare the prefix within that frame or use an unprefixed stream-namespace element.

## RFC7395-first-message-open

RFC 7395 §3.4; MUST; client; responsibility: library.

When: Immediately after the WebSocket handshake

Send an open framing element with the RFC 6120 initial stream attributes.

## RFC7395-server-open-or-close

RFC 7395 §3.4; MUST; server; responsibility: server.

When: In response to the client's initial open frame

Respond with an open or close framing element.

Scope: not-applicable. Server-only stream initiation behavior.

## RFC7395-no-multiplex

RFC 7395 §3.4; MUST NOT; client; responsibility: library.

When: For one WebSocket connection

Multiplex no more than one XMPP stream.

## RFC7395-server-stream-error-frame

RFC 7395 §3.5; MUST; server; responsibility: server.

When: When a stream error occurs

Send the complete error element in its own message and follow the required opening and closure sequence.

Scope: not-applicable. Server-only error generation behavior.

## RFC7395-websocket-closing-handshake

RFC 7395 §3.6; MUST; client; responsibility: shared.

When: After closing the XMPP stream and terminating the connection

Initiate or participate in the WebSocket closing handshake.

Scope: delegated. The library initiates closure through the browser WebSocket API, which emits the protocol-level close frame.

## RFC7395-no-redirect-downgrade

RFC 7395 §3.6.1 and 6; MUST NOT; client; responsibility: library.

When: When a close frame suggests another endpoint

Accept no endpoint with a lower security context than the current endpoint.

## RFC7395-restart-opens-new-stream

RFC 7395 §3.7; MUST; client; responsibility: library.

When: When stream negotiation mandates a restart

Open a new framed stream using the normal initiation process.

## RFC7395-restart-no-close

RFC 7395 §3.7; MUST NOT; client; responsibility: library.

When: When restarting after a negotiated feature

Do not send a close element before the new open element.

## RFC7395-no-whitespace-keepalive

RFC 7395 §3.8; MUST NOT; client; responsibility: library.

When: When keeping an XMPP WebSocket connection alive

Do not send whitespace keepalives.

## RFC7395-tls-at-websocket-layer

RFC 7395 §3.9; MUST; both; responsibility: shared.

When: When TLS protects the XMPP WebSocket connection

Use the wss URI scheme and TLS at the WebSocket layer.

Scope: delegated. The library chooses WSS and the browser performs TLS.

## RFC7395-server-no-starttls

RFC 7395 §3.9; MUST NOT; server; responsibility: server.

When: On an XMPP WebSocket stream

Do not advertise STARTTLS as a stream feature.

Scope: not-applicable. Server-only feature advertisement.

## RFC7395-client-ignore-starttls

RFC 7395 §3.9; MUST; client; responsibility: library.

When: When a WebSocket server advertises an XMPP STARTTLS feature

Ignore the feature and never attempt XMPP-layer TLS negotiation.

## RFC7395-host-meta-delegation

RFC 7395 §4 and 6; SHOULD; client; responsibility: shared.

When: When the XMPP service domain differs from the WebSocket origin

Use host-meta fetched over authenticated HTTPS to establish delegation to the WebSocket endpoint.
