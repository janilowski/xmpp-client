# RFC 6120: review notes

Migrated from the 2026-07-29 inventory. These are **unverified review notes**,
not a complete extraction or a compliance claim. Preserve IDs when adding tests;
check the original clause, its conditions and errata before implementation.
Executable coverage belongs in the standard's suite and coverage map, not here.

## RFC6120-bind-gen

RFC 6120 §7.6; MUST; server; responsibility: server.

When: When a client requests a server-generated resource

Generate a random resource identifier.

Scope: not-applicable. Server-only resource generation behavior.

## RFC6120-bind-mtn

RFC 6120 §7.3.1; MUST; client; responsibility: library.

When: After authentication when resource binding is advertised

Treat resource binding as mandatory to negotiate before normal stanza exchange.

## RFC6120-bind-restart

RFC 6120 §7.3.2; MUST NOT; client; responsibility: library.

When: After successful RFC 6120 resource binding

Do not restart the XML stream.

## RFC6120-bind-support

RFC 6120 §7; MUST; client; responsibility: library.

When: On an authenticated client stream

Support binding a resource to the stream.

## RFC6120-sasl-correlate

RFC 6120 §6.4.6; SHOULD; client; responsibility: library.

When: When authenticating a stream peer with SASL and a from address is present

Correlate the SASL authentication identity with the stream from address.

## RFC6120-sasl-errors

RFC 6120 §6.5; MUST; client; responsibility: library.

When: During SASL negotiation

Handle the defined SASL failure conditions and terminal failure flow.

## RFC6120-sasl-mtn

RFC 6120 §6.3.1; MUST; client; responsibility: library.

When: Before the stream is authenticated

Treat SASL authentication as mandatory to negotiate.

## RFC6120-sasl-restart

RFC 6120 §6.3.2; MUST; client; responsibility: library.

When: After successful SASL 1 negotiation

Initiate a fresh XML stream without closing the previous stream.

## RFC6120-sasl-support

RFC 6120 §6; MUST; client; responsibility: library.

When: For stream authentication

Support the XMPP profile of SASL.

## RFC6120-security-mti-auth-scram

RFC 6120 §13.8; MUST; client; responsibility: library.

When: When password authentication is used without TLS confidentiality

Support SCRAM-SHA-1 and SCRAM-SHA-1-PLUS for authentication.

## RFC6120-security-mti-both-external

RFC 6120 §13.8; SHOULD; client; responsibility: browser.

When: When TLS client certificates are available

Support SASL EXTERNAL with TLS.

Scope: delegated. Browser WebSocket APIs control client-certificate selection and do not expose the TLS channel directly.

## RFC6120-security-mti-both-plain

RFC 6120 §13.8; SHOULD; client; responsibility: shared.

When: When interoperating with a server that offers no stronger compatible password mechanism over authenticated TLS

Support SASL PLAIN over authenticated TLS as a last-resort mechanism.

## RFC6120-security-mti-both-scram

RFC 6120 §13.8; MUST; client; responsibility: shared.

When: When password authentication and TLS are used

Support SCRAM-SHA-1 and SCRAM-SHA-1-PLUS and prefer the channel-binding variant when available.

## RFC6120-security-mti-confidentiality

RFC 6120 §13.8; SHOULD; server; responsibility: server.

When: When providing confidentiality without authentication

Support the specified minimum TLS confidentiality profile as updated by later TLS guidance.

Scope: not-applicable. Server-only security profile.

## RFC6120-stanza-error

RFC 6120 §8.3; MUST; client; responsibility: library.

When: When generating or receiving a stanza error

Support error stanzas for message, presence, and IQ.

## RFC6120-stanza-error-child

RFC 6120 §8.3; MUST; client; responsibility: library.

When: When sending a stanza of type error

Include an error child with a valid type and defined condition.

## RFC6120-stanza-error-id

RFC 6120 §8.3; MUST; client; responsibility: library.

When: When replying with a stanza error

Preserve the triggering stanza id.

## RFC6120-stanza-error-reply

RFC 6120 §8.3; MUST NOT; client; responsibility: library.

When: When receiving a stanza of type error

Do not reply with another stanza error.

## RFC6120-stanza-extension

RFC 6120 §8.4; MUST; client; responsibility: library.

When: When a stanza contains an unsupported extension namespace

Ignore unsupported message and presence payloads, and return service-unavailable for an IQ request addressed to the client.

## RFC6120-stanza-iq-child

RFC 6120 §8.2.3; MUST; client; responsibility: library.

When: When generating or accepting an IQ stanza

Enforce the allowed child-element count for the IQ type.

## RFC6120-stanza-iq-id

RFC 6120 §8.2.3; MUST; client; responsibility: library.

When: For every IQ stanza

Require a non-empty id attribute, applying held erratum 4741 when an invalid request lacks one.

## RFC6120-stanza-iq-reply

RFC 6120 §8.2.3; MUST; client; responsibility: library.

When: When receiving an IQ get or set addressed to the client

Reply with an IQ result or error and preserve the request id.

## RFC6120-stanza-iq-type

RFC 6120 §8.2.3; MUST; client; responsibility: library.

When: For every IQ stanza

Require type to be get, set, result, or error.

## RFC6120-stanza-kind-iq

RFC 6120 §8.2.3; MUST; client; responsibility: library.

When: During normal stanza exchange

Support IQ stanzas.

## RFC6120-stanza-kind-message

RFC 6120 §8.2.1; MUST; client; responsibility: library.

When: During normal stanza exchange

Support message stanzas.

## RFC6120-stanza-kind-presence

RFC 6120 §8.2.2; MUST; client; responsibility: library.

When: During normal stanza exchange

Support presence stanzas.

## RFC6120-stream-attribute-initial-lang

## RFC6120-stream-attribute-initial-to

## RFC6120-stream-attribute-response-id

Include a stream id.

Scope: not-applicable. Server-only stream-header behavior.

RFC 6120 §4.7.3; MUST; server; responsibility: server.

Make the id unique within the server context.

Scope: not-applicable. Server-only identifier generation.

## RFC6120-stream-attribute-response-to

RFC 6120 §4.7.2; SHOULD; server; responsibility: server.

When: When responding to a stream opening

Include the initiating entity in the to attribute.

Scope: not-applicable. Server-only stream-header behavior.

## RFC6120-stream-error-generate

RFC 6120 §4.9; MUST; client; responsibility: library.

When: When detecting a fatal stream error

Send the appropriate stream error when possible, close the XMPP stream, and terminate the WebSocket transport using RFC 7395 framing.

## RFC6120-stream-fqdn-resolution

RFC 6120 §3.2; MUST; client; responsibility: library.

When: Before opening the RFC 6120 TCP transport

Resolve the service using the RFC 6120 DNS procedure.

Scope: replaced. The target profile replaces the TCP binding and its DNS procedure with RFC 7395 WebSocket discovery and XEP-0156.

## RFC6120-stream-negotiation-complete

RFC 6120 §4.3.5; MUST NOT; client; responsibility: library.

When: While mandatory stream features remain

Do not consider negotiation complete or send normal stanzas until only voluntary features remain.

## RFC6120-stream-negotiation-features

RFC 6120 §4.3.2; MUST; server; responsibility: server.

When: After sending a response stream header

Advertise stream features.

Scope: not-applicable. Server-only stream-feature advertisement.

## RFC6120-stream-negotiation-restart

RFC 6120 §4.3.3; MUST; client; responsibility: library.

When: After negotiating a feature that requires restart

Replace the previous stream and send a new opening frame according to RFC 7395.

## RFC6120-stream-reconnect

RFC 6120 §3.3; MUST; client; responsibility: library.

When: After an unexpected transport termination when reconnection is enabled

Reconnect using exponential backoff rather than a rapid fixed retry loop.

## RFC6120-stream-tcp-binding

RFC 6120 §3; MUST; client; responsibility: library.

When: For the RFC 6120 transport binding

Bind the XML stream to TCP.

Scope: replaced. RFC 7395 replaces TCP framing with one independently parsable XML frame per WebSocket message.

## RFC6120-tls-certs

RFC 6120 §13.7.2; MUST; client; responsibility: browser.

When: When the TLS peer presents a certificate

Authenticate the server identity using the applicable service-identity rules.

Scope: delegated. The browser performs WSS certificate-path and endpoint-host validation; discovery trust still requires library evidence.

## RFC6120-tls-mtn

RFC 6120 §5.3.1; MUST; client; responsibility: browser.

When: When STARTTLS is advertised as mandatory on the TCP binding

Treat STARTTLS as mandatory to negotiate.

Scope: replaced. RFC 7395 section 3.9 moves TLS below XMPP to the secure WebSocket layer and requires clients to ignore XMPP STARTTLS features.

## RFC6120-tls-restart

RFC 6120 §5.3.2; MUST; client; responsibility: browser.

When: After STARTTLS succeeds on the TCP binding

Restart the XML stream.

Scope: replaced. WSS completes TLS before the XMPP subprotocol starts, so no XMPP-layer TLS restart occurs.

## RFC6120-tls-support

RFC 6120 §5; MUST; client; responsibility: shared.

When: For an XMPP connection

Use TLS to protect the stream.

Scope: delegated. RFC 7395 provides TLS through WSS; the browser implements TLS while the library selects and enforces secure endpoints.

## RFC6120-tls-correlate

RFC 6120 §13.7.2; SHOULD; client; responsibility: shared.

When: When a stream from address and authenticated TLS identity are available

Correlate the authenticated peer identity with the XMPP stream identity.

Scope: delegated. The browser hides certificate details, while the library controls XMPP domain and discovery decisions.
