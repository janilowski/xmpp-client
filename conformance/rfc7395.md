## Test strength

The transcript normalizer shares `saxes` with production: it is not an independent
parser oracle. Literal negative vectors assert rejection before delivery. Real
Chromium tests use native `DOMParser` for outgoing documents and exercise malformed
peer frames. They supplement, rather than replace, Prosody interoperability.

Five mutations exercise incomplete-document acceptance, wrong namespace error,
missing subprotocol validation, missing stanza namespace and wrong destination.
Each must fail an assertion, not merely crash or time out.

## Discovery policy and former DNS skip

The resolver implements HTTPS host-meta, not DNS SRV. The skipped public-domain
test expected obsolete SRV/address results. Scoped fetch tests now cover the
implemented contract without Internet-dependent fixtures.

All HTTP redirects are rejected, including secure redirects. This conservative
policy avoids silent origin/scheme changes but can reject otherwise valid hosting
setups; it is not an RFC requirement to reject every redirect. Explicit `ws`/`http`
discovery endpoints remain supported; applications must impose their TLS policy.

## Size and parser choice

Complete-document validation uses `saxes` 6, retaining `ltx` element compatibility
and the exported legacy parser API. Full minified bundle: 19.46 KB Brotli versus
12.69 KB before this work; budget 20 KB. These are compressed distribution sizes,
not source-code sizes. Saxes is archived upstream. Review its maintenance risk and
the cost of retaining two parsers before a separate bundle optimization; do not
replace validation with partial checks merely to meet the previous budget.
