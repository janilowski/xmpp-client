# RFC 7395 coverage map

Source: [RFC 7395, October 2014](https://www.rfc-editor.org/rfc/rfc7395.html).
Client role over WebSocket. Clause review: 2026-09-15; external updates/errata
must still be checked before claiming complete standards coverage.

Suite: [rfc7395.test.ts](rfc7395.test.ts). Names start with source sections.
Additional adapter tests: [subprotocol.test.js](../src/websocket/test/subprotocol.test.js).
This map records **coverage boundaries, not pass/fail results**.

Historical [requirement IDs](notes/rfc7395.md) remain available. Tests cover
request-subprotocol, reject-missing-subprotocol (adapter only), outgoing parts
of text-utf8/framing-namespace/standalone-xml/frame-first-character/
one-element-per-frame/first-message-open, restart-opens-new-stream/restart-no-close,
and the normal websocket-closing-handshake path. No other IDs are implied covered.

## Oracle and strength

Expected XML is literal and parsed independently with namespace-aware `saxes`.
Attribute order, prefix spelling and empty-element spelling are not requirements.
Each WebSocket message is validated independently. Harness tests reject multiple
roots, truncation, unbound prefixes, duplicate attributes and trailing garbage,
and accept numeric references. These check the **oracle**, not production
handling of malicious input.

Mutations remove the selected-subprotocol guard, omit the outgoing stanza
namespace, and change the destination domain. Each has a passing baseline and
must fail an assertion in a disposable source copy. This explicit mutation set
is not a project-wide mutation score.
