# RFC 7395 client coverage

Source: [RFC 7395](https://www.rfc-editor.org/rfc/rfc7395.html), reviewed
2026-09-16, including RFC 6120 §4.7 stream attributes.
The [RFC Editor errata search](https://errata.rfc-editor.org/search/?rfc_number=7395)
returned no matching errata on that date.

Every direct client obligation below has executable scenarios or an explicit
platform/server boundary. This is **client WebSocket binding coverage**, not
certification of all referenced standards, all inputs, or every browser.
RFC 6120 authentication/IQ, RFC 7622 and XEP-0198 remain separate
[roadmap work](roadmap.md), not implicitly completed by this suite.

## Explicit policies

- Version `1.x` is supported, including numeric leading zeros and higher minor
  versions. Missing version denotes unsupported pre-1.0 semantics.
- Legacy missing server `from`/`to` is tolerated as RFC 6120 recommends.
  The client does not fabricate a server ID or language. Caller-selected
  outgoing language is included; no user language is guessed. Explicit
  `xml:lang=""` remains a reset. Incoming frames never inherit context.
- Discovery uses authenticated HTTPS and automatically selects WSS only.
  Explicit `ws://` remains available for deliberate application/local policy.
  Rejecting all HTTP redirects is conservative policy, not an RFC mandate.
- XML document limits: 1 MiB UTF-8, 64 element levels. These are local policy,
  not RFC-prescribed values. Host-meta reading stops at the byte limit.
  Browser WebSocket messages are already buffered before delivery: these limits
  cannot bound native transport allocation before the library receives data.

## Test strength and platform boundaries

The transcript normalizer shares Saxes with production. Literal rejection vectors
and Chromium DOMParser provide additional independent oracles. Nine mutations
must fail assertions, not merely crash/time out: version, language, byte/depth
limits, incomplete XML, namespace error, subprotocol, stanza namespace, destination.

Positive Chromium interoperability trusts one disposable key with an SPKI
exception; it **does not prove hostname/expiry checking**. The separate Bun CA
suite does. Trusted-CA matrices for Chromium/Firefox/WebKit remain platform
expansion work; this suite does not claim all browsers. The known Bun IPv6 TLS
defect remains an explicit expected failure, not a successful identity check.

## Bundle

One Saxes engine serves document and stream parsing. Ltx supplies tree building
and serialization. No production dependency added. Bundle: 19,730 bytes Brotli
(previously 19,455; +275), below the unchanged 20 KiB budget. Saxes 6 is archived
upstream; its maintenance risk remains visible.
