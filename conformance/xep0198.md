# XEP-0198: counters and resumption

Source: [XEP-0198 1.6.3](https://xmpp.org/extensions/xep-0198.html),
reviewed 2026-09-16, §§4–6 and §13 schema. This is the bounded #13 fix,
not complete XEP-0198 compliance.

| Requirement / policy                                                                             | Evidence                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `h` is an unsigned 32-bit integer, not arbitrary JS numeric syntax                               | [Counter vectors](../src/stream-management/counters.test.js): missing, empty, negative, oversized, fractional, exponent, hexadecimal, nonnumeric; valid XML whitespace, plus sign and leading zeros |
| Acknowledgement distance cannot exceed outstanding stanzas                                       | Empty/nonempty queues; validate before emitting any ack or removing any stanza                                                                                                                      |
| Counters wrap from 4294967295 to zero                                                            | Inbound wire value, outbound partial acknowledgement across rollover, repeated acknowledgement and ordered suffix                                                                                   |
| Over-ack generates `undefined-condition` with sibling `handled-count-too-high`, then closes (§6) | [Real WebSocket scenarios](xep0198.test.ts); diagnostic `h` and `send-count`                                                                                                                        |
| Resumption applies `h` before replay, without counting retransmissions twice (§5)                | Stream-feature and SASL2 integration vectors; partial acknowledgement across rollover, replay suffix and final acknowledgement                                                                      |
| Failed resumption can carry an optional handled count (§5)                                       | Both resumption paths acknowledge that prefix before failing the remaining queue                                                                                                                    |
| Invalid resumption cannot enable SM or replay its queue                                          | Both resumption paths reject impossible counts atomically                                                                                                                                           |
| Disconnected-session queues cannot be consumed by ordinary acknowledgements                      | Disabled-session regression; #12 cancellation suite covers delayed replay                                                                                                                           |

Malformed `h` closes with `bad-format`: a local policy for invalid XML-schema
values. A backwards count with no possible wrap within the outstanding queue is
an impossible acknowledgement, not a counter reset. Missing `h` is allowed only
on `<failed/>`; then all pending stanzas fail as before.

`sm.outbound` retains its existing meaning: the last acknowledged outbound
sequence, not the total sent. Total sent modulo 2³² is that value plus queue
length. Counters can be seeded near the boundary in unit tests to avoid sending
billions of stanzas; wire tests establish error shape and transport closure.

[Mutation checks](mutations.ts) require assertion failures when counter validation
is silently bypassed or inbound rollover is removed. Run `bun run test:all` for
unit, conformance, mutation, Prosody and browser gates.

Remaining XEP-0198 review includes enable/resume attribute negotiation, session
identity/lifetime/location policy, application-level handling semantics and
the full normative requirement map. Queue memory limits are separate policy;
this patch does not introduce persistence or promise exactly-once delivery.
